Design principle: Each layer only talks to the layer directly above and below it. Changing the AI model does not affect the API. Adding a source does not affect the frontend.

Local LLM produces structured intelligence for every publication. No external API. No cost.

→

Three AI tasks per publication

TaskInputOutput
Summarizetitle + 800 chars of abstract6-section summary (topic, purpose, findings, developments, policy, relevance)
Classifytitle + abstract1–3 slugs from 11 canonical topics
Relevancetitle + abstract2–3 sentences on BoT relevance + disclaimer

Three safeguards

Fallback engine

If Ollama is down → rule-based keyword matching. Pipeline never stalls.

Topic validation

LLM output is validated against topics.py. Hallucinated slugs dropped.

Never empty

Institution-aware default topic — every processed publication ends with at least 1 topic.

Traceability

ai_engine column records "ollama" or "rule-based" for every row.

Model choice: qwen2.5:3b — small, local, CPU-friendly. Zero API cost, data never leaves the machine. Accuracy ~65–75% top-1 on the manual eval sample.

6. Database — Design Decisions

Why these choices

DecisionReason
SQLite over PostgreSQLZero-setup, single file, portable. Swap by changing one env var.
Fingerprint UNIQUEDB enforces dedup — even if code has a bug, no duplicate rows.
AI columns nullablePublication stored first; enriched second. Pipeline never blocks on AI.
Topics as comma-separated stringsFast, simple, good enough. Upgrade path: join table.
hidden instead of deleteNon-destructive. Admins can restore. Traceability preserved.
Source table separate from built-insBuilt-ins have custom parsers. Only dynamic feeds go in the table.
Rule matches stored, not computedAvoids re-scanning all pubs every time alerts are viewed.

Known limitations

LimitationImpactFix path
Users in memory, not DBLogins reset on restartAdd User model + hashed passwords
ai_topics as stringHarder SQL joinsAdd publication_topics M2M
No FK constraintsOrphan rows possibleAdd ON DELETE CASCADE
SQLite write concurrencyLocks under heavy loadSwitch to PostgreSQL

Sample queries

Count by source: SELECT institution, COUNT(*) FROM publications WHERE hidden=0 GROUP BY institution;

Fallback rows: SELECT id, title FROM publications WHERE ai_engine='rule-based';

Recent rule matches: SELECT r.keyword, p.title FROM rule_matches m JOIN alert_rules r ON r.id=m.rule_id JOIN publications p ON p.id=m.publication_id ORDER BY m.matched_at DESC LIMIT 10;

Traceability guarantee: Every AI-generated output stores its engine and links back to source_url — the original document can always be verified.
